# 2026.293.1944 — chore(deps): pin the python layer past its floor-check fix, and let the HTTP check wait for first boot

## Summary

Two changes with one purpose: make this candy's check bed **reachable and green**, which
is the R10 witness opencharly/pod-openwebui#12 could not obtain.

**1. The `layer-python` pin moves past its floor-check fix** (`v2026.273.1820` →
`v2026.293.1922`). The old tag carried a hard-coded "CPython 3.13" assertion. This image
runs **3.12.13**, because upstream open-webui requires `>=3.11,<3.13` — so every bed
built from this candy died in `check-image` on those two layer checks and its entire
runtime half never executed. `layer-python` now asserts a floor instead
(opencharly/layer-python#8 → #9, merged as `v2026.293.1922`).

**2. The HTTP probe waits for the app instead of assuming it is up.** Open Web UI runs
its Alembic migrations and builds the model cache *before* uvicorn binds, so on a cold
deployment a single unconditional GET reaches the port forwarder with nothing behind it
and is reset. Measured: the whole live phase failed on this step ~8s into a cold bed.
The fix is the engine's readiness primitive, not a sleep in a shell step:

```yaml
- check: the Open WebUI web interface answers HTTP 200 on the published port
  timeout: 30s
  eventually: 3m
  retry_interval: 2s
  context: [runtime]
  http:
    http: http://127.0.0.1:${HOST_PORT:8080}/
    status: 200
```

`eventually` probes readiness in the check engine (bounded, observable, counted in the
report) and the same single request still asserts steady state once the app is up.
