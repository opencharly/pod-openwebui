# 2026.243.1016 — docs: narrow a changelog ref list that counted prose as pins

## Summary

Narrows the ref list in `CHANGELOG/2026.243.0516.md`, the entry for PR#3, which presented every
changed ref as a dependency **pin**. 1 of them are not.

Those 1 live inside `content:`/`description:` block scalars — usage examples inside skill
documents — which charly parses as opaque strings and never resolves. They moved no dependency
edge and never contributed to a `resolved to multiple versions` warning.

**This entry is only partly wrong, and the correction is deliberately narrow.** That release
*did* advance real pins, its justification holds for those, and its attribution tier is left
exactly as it was — real configuration changed, so the tier remains defensible. Only the scope
of the ref list is corrected. A clarification is added under the Summary; nothing else in the
entry is touched.

## Root cause

The scanner in use when that PR was written matched refs with a plain regex over the whole
file. A YAML example printed inside documentation is textually identical to a real dependency
entry — both render as `  - '@github.com/opencharly/x:vY'` — so it could not tell them apart
and swept documentation strings in alongside genuine pins.

It has since been replaced with a block-scalar-aware parser, which is what identified the
subset below.

## How tested

Each prose ref is shown with its enclosing block-scalar opener and the decisive check: the
count of lines between that opener and the ref which would CLOSE the block — zero in every
case. Reproducible with `sed -n '<opener>p;<ref>p' charly.yml` at the commit named below.

The evidence is generated from the file state **that release produced**, not from today's
tree, since that is what the entry describes.

Independently, charly's own behaviour confirms the distinction — `:vTAG` is unresolvable, so a
real ref set to it fails the gate while a prose ref does not:

```
control: pod-hermes (5 real resolving refs), one real ref set to :vTAG
$ charly box validate ; echo "exit=$?"
charly: error: command "validate": validation error: downloading
  github.com/opencharly/layer-ffmpeg:vTAG: InvokeProvider refs:refs op=resolve: resolving ...
exit=1
```

This commit edits one changelog file. No content ships, so no candy version is bumped:
correcting a historical record is not a release.
