# 2026.318.2255 — feat(openwebui): auto-configure OpenAI-compatible speech (TTS) from a provided server

## Summary

Open WebUI's `openai` speech engine is driven entirely by `AUDIO_TTS_*` env, and until now this
candy could not be given a provider at all: no `AUDIO_TTS_*` name existed anywhere in the org, and
`openwebui-entrypoint` had no speech section, so a speech-providing candy could declare
`env_provide` and `charly config --update-all` would filter it out.

This adds the **consume side** of that contract, plus the audio capability the image was missing:

- **`env_accept`**: `QWEN3_TTS_HOST`, `QWEN3_TTS_SERVED_MODEL`, `QWEN3_TTS_VOICE`, `QWEN3_TTS_API_KEY` —
  the names a speech-providing candy provides. All FOUR are declared because the entrypoint reads all
  four: an undeclared provide is silently filtered out by `charly config --update-all` (round 2's
  finding).
- **`openwebui-entrypoint`**: one block projecting them into the `AUDIO_TTS_*` **pair**. The pairing
  is load-bearing: `AUDIO_TTS_OPENAI_API_BASE_URL` defaults to `OPENAI_API_BASE_URL`, which on a pod
  with an LLM provider is the **chat** server, so an engine set alone posts speech requests at the
  wrong service (surfacing as "Server Connection Error"). `AUDIO_TTS_OPENAI_API_KEY` is pinned for
  the same reason — it inherits the chat credential. `response_format` defaults to `mp3`.
- **`require: '@github.com/opencharly/layer-ffmpeg:v2026.272.0056'`**: pydub is a hard dependency of
  `open-webui` and the ffmpeg **binary** was absent, so Open WebUI's non-MP3 transcode path raised and
  turned a WAV reply into a 500 (closes #20). With the binary present, a WAV provider works too;
  `response_format=mp3` stays the default because the consumer's speech cache is `.mp3`-named and the
  transcode is then skipped.
- **Two build-scope witnesses**: the projection fires with the provide, and invents nothing without
  it (no `context:` on purpose, so `check live`'s verify-only mode cannot skip them).

**Live, end to end** — a real Qwen3-TTS provider pod, wired by charly, no hand-edited env:

```
$ charly config qwen3-tts
  Env provides injected: QWEN3_TTS_HOST=http://charly-qwen3-tts:8000/v1
  Env provides injected: QWEN3_TTS_SERVED_MODEL=Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice
  Env provides injected: QWEN3_TTS_VOICE=vivian

$ charly config openwebui --update-all
  Environment=QWEN3_TTS_HOST=http://charly-qwen3-tts:8000/v1      # written into the quadlet

# read from the RUNNING Open WebUI process's /proc/<pid>/environ:
AUDIO_TTS_ENGINE=openai
AUDIO_TTS_OPENAI_API_BASE_URL=http://charly-qwen3-tts:8000/v1
AUDIO_TTS_MODEL=Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice
AUDIO_TTS_VOICE=vivian
AUDIO_TTS_OPENAI_API_KEY=not-needed
AUDIO_TTS_OPENAI_PARAMS={"response_format":"mp3"}

# the provider, serving real speech:
POST http://charly-qwen3-tts:8000/v1/audio/speech → 200, 261164 bytes, audio/wav (RIFF), 15.2s

# and through Open WebUI's OWN handler (authenticated admin):
POST /api/v1/audio/speech → 200, 22892 bytes, audio/mpeg, ID3 header, 3.12s
```

The ffmpeg half is proven at its own boundary inside the running pod: `command -v ffmpeg` →
`/usr/bin/ffmpeg`, and a real WAV→MP3 transcode (`TRANSCODE_OK`, 2828 bytes) — the step that
previously 500'd.

  `/charly-check:check`, `/charly-build:secrets`, `/charly-internals:git-workflow` loaded before any

- **R6** — no unrelated work touched; the change is one branch off fresh `origin/main`.
- **R7** — `entrypoint-tts-projection` fails without the change: it asserts the engine, the exact
  provider base URL, the params default and the API key default — every value the projection
  produces, none of which exist before this diff. It does **not** assert `AUDIO_TTS_MODEL` or
  `AUDIO_TTS_VOICE`; the body previously implied it did, and this line now says what the witness
  actually checks.
  `entrypoint-tts-absent` passes either way **by design** — it is a regression guard that no engine
  is invented when no provider is present, not a proof of the change. (Corrected in review round 1:
  the earlier body claimed both failed without the change.)
- **R8** — the live provider is a real service (Qwen3-TTS), not a mock.

## Change classification

- **Behaviour**: a deployment that has a speech provider now gets TTS auto-configured; a deployment
  without one is unchanged (nothing is invented).
- **Image**: `ffmpeg` is now installed in every image composing this candy (a few tens of MB).
- **Rollback**: revert the commit; the entrypoint block is inert without `QWEN3_TTS_HOST`, so a
  revert needs no follow-up data or config migration.
