# 2026.243.2104 — docs: use an unpinned ref in skill examples, not a vTAG placeholder

## Summary

This repo's skill prose used `:vTAG` as a stand-in so documentation examples would not carry a
CalVer that goes stale the week after it is written. That solved staleness and introduced a worse
problem: **`vTAG` does not resolve.** A reader copying the example into a `charly.yml` gets a
resolution failure.

It also escaped this repo. `charly marketplace generate` projects this prose into the published
corpus, which shipped ~80 such lines across 42 `SKILL.md` files and **blocked the org-wide refs
refresh** — opencharly/marketplace#260, BLOCKED on *"non-resolvable `vTAG` pins shipped into the
corpus"*.

2 placeholder(s) here:

```
-                - '@github.com/opencharly/layer-agent-forwarding:vTAG'
+                - '@github.com/opencharly/layer-agent-forwarding'
-                - '@github.com/opencharly/pod-dbus:vTAG'
+                - '@github.com/opencharly/pod-dbus'
```

## Why unpinned rather than restoring a CalVer

An unpinned `@github` ref is strictly better than either previous form. charly resolves it to the
repo's newest tag, so the example **works when copied** and **never goes stale**:

```
$ charly box validate
Resolved @github.com/opencharly/pod-dbus -> v2026.239.1555 (latest tag)
charly box validate: OK — 0 warnings, 0 errors
```

That is a live probe, run against a scratch project with a single unpinned ref, confirming the
form resolves rather than assuming it does. Restoring a hardcoded CalVer would fix the reviewer's
objection and reintroduce the staleness the placeholder existed to avoid; the unpinned form
resolves both.

## How tested

```
$ git diff --stat origin/main...HEAD
charly.yml | 4 ++--
 1 file changed, 2 insertions(+), 2 deletions(-)
```

**Only EXAMPLE refs are rewritten; inline notation is preserved.** `:vTAG` appears in two senses
in this corpus — as an example pin, and as metasyntactic notation inside explanatory prose:

```
- '@github.com/opencharly/layer-supervisord:vTAG'   <- an example pin: rewritten
"The git `:vTAG` is only the FETCH coordinate."     <- notation in prose: left alone
```

An earlier revision of this campaign stripped the token from *all* occurrences and left
`The git `` is only the FETCH coordinate.` in a sibling repo — an empty code span and a broken
sentence, which the reviewer caught. A token-level guard cannot see that: it verifies the token
was removed, not that the result reads correctly. The rewrite now matches only a YAML list item
whose entire value is a quoted `@github` ref, and every other occurrence is left untouched.

**No entity `version:` stamp is bumped, deliberately.** The corpus picks up new prose when its
refs list advances, not from the stamp. A stamp bump here is also actively hazardous: in
`pod-charly-core` the nearest `version:` line above one of these placeholders lives **inside a
documentation block scalar**, so a naive backward scan would have rewritten an example rather than
a stamp. That was caught before it shipped and the stamp logic was removed rather than patched.

## Rulebook compliance

- **R1 (RCA)** — root-caused to the projection path: prose in this repo's `skill:` entity is
  generated into the published corpus, so a non-resolvable placeholder here becomes a
  non-resolvable example there. Confirmed by tracing the blocked corpus PR's diff back to this
  repo's commit.
- **R3 (no duplication)** — prose only; no logic, packages, or plan steps.
- **R4 (no workarounds)** — the placeholder is replaced with a form that actually resolves, not
  suppressed or annotated around.
- **R5 (delete legacy)** — every `:vTAG` in this repo is removed, not just the ones the corpus
  happened to surface.
- **R6 (git safety)** — feature branch, no force-push, no hook bypass.

## Change classification

- **Change class:** documentation — `skill:` prose only. No packages, services, plan steps,
  dependency edges, or entity-version stamps.
- **Verification gate:** placeholder-only diff verified mechanically (`unmatched-lines=0`), plus a
  live `charly box validate` probe confirming the replacement form resolves.
- **Attribution tier:** `documentation reviewed` — a prose-only change. The replacement form was
  verified live, but this diff ships no runtime path of its own, so a runtime tier would overstate
  it.
