# 2026.319.0820 — feat(openwebui): consume a whisper STT server via env_provide/env_accept

## Summary

This is the **demand side** of speech-to-text: the `openwebui` candy learns to consume a whisper ASR server through charly's existing discovery, so a deployment gets STT **without anyone hand-typing an `AUDIO_STT_*` variable**.

- `env_accept: WHISPER_BASE_URL`, `WHISPER_MODEL` — auto-injected by `opencharly/layer-whisper`'s `env_provide`.
- `secret_accept: WHISPER_API_KEY` reading the **same** `charly/api-key/whisper` key the server reads, so both ends agree on one credential.
- One conditional block in `openwebui-entrypoint` that projects the whole STT contract from that single URL.

The block encodes four things that were **measured** in Open Web UI 0.13.3 (the version this candy pins) and that each fail silently or as a 500 if missed:

| trap | what the entrypoint does |
|---|---|
| the engine value for the built-in local engine is `''`, and **`local` is not a value at all** | sets `openai` explicitly |
| the client **appends** `/audio/transcriptions`, so the base must end in `/v1` | strips a trailing slash and forwards the provider's `/v1` base |
| `AUDIO_STT_OPENAI_API_KEY` **defaults to `OPENAI_API_KEY`** — so an unset value in a keyed whisper deployment ships the *chat* provider's credential to the ASR server and takes a 401 | forwards `WHISPER_API_KEY` explicitly when it is present |
| an empty `AUDIO_STT_MODEL` is legal (`model=` is sent) | forwards `WHISPER_MODEL` **only when supplied**; no model name is fabricated — the server answers with the checkpoint **it** serves |

And the `else` branch is the load-bearing half: with no whisper server provided, the entrypoint **leaves the upstream local default and says so** in the log. Without it, every deployment in the org that has no whisper server would still advertise `engine=openai` and turn every voice memo into a `500`.

Two **build-scope** stub checks assert both arms by capturing what the entrypoint *would*
exec — the same pattern the candy already uses for `entrypoint-openai-key-alone`:

```
PASS  with a whisper server provided the entrypoint projects the remote STT engine  [entrypoint-whisper-present]
PASS  with no whisper server the entrypoint claims no remote STT engine             [entrypoint-whisper-absent]
```

Both arms are asserted field by field, including **the key-forwarding branch** (the trap above):

- *present* — `WHISPER_BASE_URL`, `WHISPER_MODEL=base` **and `WHISPER_API_KEY=probe-whisper-key`** are
  supplied; the stub echoes what it received, and the check asserts `STT_ENGINE=openai`,
  `STT_BASE=http://charly-whisper:9000/v1`, `STT_MODEL=base` and **`STT_KEY=probe-whisper-key`** —
  so removing the forwarding branch turns this check red.
- *absent* — no whisper variables at all: the check asserts `STT_ENGINE=` (empty, upstream local
  default) **and `STT_KEY=`** (empty), proving the key is not forwarded when none is provided.

## Rulebook compliance

- **R0** — skills loaded: `openwebui`, `openwebui-layer`, `pod`, `layer`, `check`, `deploy`, `charly-config`, `disposable`, `strict-policy`, `git-workflow`.
- **R1** — the two projection arms are asserted rather than assumed, and the first attempt at the end-to-end probe failed (Open Web UI rejected a `.flac` sent as `application/octet-stream`) which was root-caused to its content-type gate and fixed in the probe, not worked around.
- **R2** — one block, one place: no second copy of the STT mapping anywhere, and the entrypoint keeps the same conditional style as the existing Ollama/OpenAI projections.
- **R3** — **no fabricated defaults**: the earlier draft of this change carried `AUDIO_STT_MODEL="${WHISPER_MODEL:-whisper-1}"` and `AUDIO_STT_OPENAI_API_KEY="${WHISPER_API_KEY:-charly}"`. Both are removed — an invented model id or placeholder key makes an unconfigured deployment *look* configured, which is exactly the hidden-fallback pattern R3 forbids. The measured credential-inheritance trap replaces them.
- **R4** — product before prose: the `env_accept` declarations and the projection land together, so `charly config` actually injects what the entrypoint reads.
- **R5** — nothing legacy is left behind; the entrypoint's new branch has an explicit `else` rather than a silent fall-through.
- **R6** — session worktree off fresh `origin/main`; no destructive git action.
- **R7** — the joint bed's assertion is **end-to-end through Open WebUI**; a raw ASR curl would pass even if the projection never happened, which is the false pass this step exists to prevent.
- **R8** — the live pair ran live against a real ASR server; nothing mocked.
- **R9** — the worktree-local CalVer binary `2026.318.1348` built and drove everything.
- **R10** — the joint bed ran on a `disposable: true` pair with a fresh rebuild and teardown.

## Change classification

**Breaking change + rollback:** additive. A deployment that provides `WHISPER_BASE_URL` now switches `AUDIO_STT_ENGINE` from the built-in local engine to a remote OpenAI-compatible one; a deployment that provides nothing is unchanged (the `else`). Rollback is a revert of this PR — no data is migrated, and Open Web UI's config is env-authoritative (`ENABLE_PERSISTENT_CONFIG=false`), so the previous state returns on the next start.
