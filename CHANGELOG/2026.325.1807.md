# 2026.325.1807 — fix(openwebui): every provider projection is a default, so the operator's env wins

## Summary

Makes the Open Web UI entrypoint **default** its provider wiring instead of **overwriting** it, so a
deployment can set the service's own environment variables and keep them
(opencharly/pod-openwebui#29).

**The defect, measured.** Every provider-derived assignment was an unconditional `export`, run
whether or not the operator had set that variable:

| Open Web UI's own variable | what the entrypoint did |
|---|---|
| `OPENAI_API_BASE_URLS` / `OPENAI_API_KEYS` | replaced whenever `OPENROUTER_API_KEY`, `OLLAMA_API_KEY` or `OPENAI_API_KEY` was present |
| `ENABLE_OLLAMA_API`, `OLLAMA_BASE_URL` | forced `true` + the provided host, or forced `false` with no `OLLAMA_HOST` |
| `AUDIO_TTS_ENGINE`, `AUDIO_TTS_OPENAI_API_BASE_URL`, `AUDIO_TTS_OPENAI_API_KEY`, `AUDIO_TTS_MODEL`, `AUDIO_TTS_VOICE` | all replaced when `QWEN3_TTS_HOST` was present |
| `AUDIO_STT_ENGINE`, `AUDIO_STT_OPENAI_API_BASE_URL` | replaced when `WHISPER_BASE_URL` was present |
| `VECTOR_DB`, `QDRANT_URI` | replaced when `QDRANT_URL` was present |
| `TOOL_SERVER_CONNECTIONS` | replaced when `CHARLY_MCP_SERVERS` named any MCP server |
| `CODE_EXECUTION_*` / `CODE_INTERPRETER_*` | replaced when that MCP set contained a server named `jupyter` (or a url carrying `8888/mcp`) — the Jupyter-provider detection, not `CHARLY_MCP_SERVERS` wholesale |

The operator's value was discarded silently — the process simply started with the entrypoint's.

**The fix.** Every one is now `${VAR:-derived}`: the operator's explicit value always wins, and the
derivation fills only what was left unset. Two places needed more than a one-line default:

- **Ollama without a provider.** With `OLLAMA_BASE_URL` set and no `OLLAMA_HOST`, the old code kept
  the operator's URL but forced `ENABLE_OLLAMA_API=false` — an enabled-looking value that was
  ignored. The switch now defaults ON when the operator's URL is present.
- **`TOOL_SERVER_CONNECTIONS` and the Jupyter `CODE_*` values** are derived into a `*_DERIVED`
  variable first, because JSON carrying quotes cannot sit inside a `${VAR:-…}` written into a
  double-quoted string.

**Four checks carry the contract in-image.** Three of them have a pre-fix red recorded below; the
fourth, `entrypoint-jupyter-projection`, is a **regression guard** — it asserts the values the
pre-fix file already emitted, so it passes before and after, and its job is to catch over-defaulting:

| check | asserts |
|---|---|
| `entrypoint-operator-env-wins` | the operator's OpenAI/Ollama/TTS/STT/vector/MCP values survive — **red before** (all of them replaced) |
| `entrypoint-jupyter-projection` | the derived `CODE_*` set when the operator is silent — **regression guard**, green before and after |
| `entrypoint-code-env-wins` | the operator's `CODE_EXECUTION_*` and `CODE_INTERPRETER_*` values survive — **red before** |
| `entrypoint-ollama-url-enables` | an operator `OLLAMA_BASE_URL` with no `OLLAMA_HOST` enables the provider — **red before** |

**Skill.** `.agents/skills/openwebui/SKILL.md` gains the "every projection is a default, the
operator always wins" paragraph, so the documented contract and the code cannot drift.

**Note on the `CI_TOKEN` line (answered in round 3).** The old entrypoint's embedded Python computes
`jupyter_token = sys.argv[2]`, i.e. `${CODE_EXECUTION_JUPYTER_AUTH_TOKEN:-}`, and then runs

```
print(f'export CODE_EXECUTION_JUPYTER_AUTH_TOKEN="{jupyter_token}"')
print(f'export CODE_INTERPRETER_JUPYTER_AUTH_TOKEN="{jupyter_token}"')
```

**both** slots from that one value. The `entrypoint-code-env-wins` arm sets both operator variables:

```
CODE_EXECUTION_JUPYTER_AUTH_TOKEN=operator-exec-token      (charly.yml, this check)
CODE_INTERPRETER_JUPYTER_AUTH_TOKEN=operator-interp-token
```

so `jupyter_token` is non-empty, the block runs, and the operator's distinct interpreter token is
overwritten by the exec token — which is exactly the `CI_TOKEN=operator-exec-token` shown above. The
review read the arm as supplying no provider token; it supplies one, and the red is reproducible from
the committed check.
