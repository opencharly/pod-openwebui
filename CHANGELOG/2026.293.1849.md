# 2026.293.1849 — feat(openwebui): pin open-webui 0.12.3 and prove the entrypoint against it

## Summary

The candy's pixi environment locked **open-webui 0.9.5** while `pixi.toml` declared
the dependency as a wildcard (`open-webui = "*"`), so the lock was the only pin and
the version had floated three minors behind. This pins **`==0.12.3`** (PyPI latest)
and regenerates `pixi.lock`, then carries the entrypoint through the upgrade with
evidence instead of assumption.

Auditing the 0.9.5 → 0.12.3 delta against the real 0.12.3 source (sdist compared
against a 0.9.5 sdist taken the same way; release notes used only for intent) found
the env names unmoved, but three load-bearing changes and one pre-existing defect in
the JSON this repo owns:

| Surface | Verdict |
|---|---|
| `DATA_DIR`, `DOCKER`, `ENABLE_DIRECT_CONNECTIONS`, `ENABLE_CODE_EXECUTION`, `ENABLE_VERSION_UPDATE_CHECK`, `WEBUI_AUTH`, `WEBUI_ADMIN_EMAIL/PASSWORD/NAME` + the admin first-run path, `OLLAMA_BASE_URL`/`ENABLE_OLLAMA_API`, `OPENAI_API_KEY`/`OPENAI_API_BASE_URL` (still folded into the plural lists), `TOOL_SERVER_CONNECTIONS` (superset model), `CODE_EXECUTION_ENGINE` + `CODE_EXECUTION_JUPYTER_*` | **unchanged**, name and semantics |
| `WEBUI_SECRET_KEY` | **now a hard requirement** — `env.py:770-786` raises `SystemExit` under `WEBUI_AUTH` where 0.9.5 defaulted to `t0p-s3cr3t`. The candy already provisions it as a podman secret, so this is documented, not changed |
| `PORT` | **never read from the environment — in either version** (`serve(host, port: int = 8080)` is a Typer option). The wrapper now passes `--port "${PORT:-8080}"`, so the declared env actually binds |
| `ENABLE_PERSISTENT_CONFIG` | name/semantics unchanged, **mechanism rewritten** — `PersistentConfig` and `/opt/data/config.json` are gone; env-built defaults in a per-key config table. The `false` default is what stops the legacy `config.json` import (`config.py:86-93`) from overriding this wiring |
| MCP `info.id` | **defect fixed** (pre-existing, both versions): every connection carried `""`. Upstream builds the tool id as `server:mcp:<id>` and keys the client map, the OAuth client and the access-control lookup on it, so an empty id collapses all servers onto one identity and a second server's tools are unreachable. It now carries the server name, unique by the `mcp_provide` contract |

### Documented claims the live run falsified, corrected here

Deploying this candy proved two of its own docs wrong, so they are fixed rather than
left asserted:

- **`charly secrets get …` does not work.** The `secrets` command plugin is not in the
  default binary — `charly secrets` answers with usage, from a candy-loaded project
  too, on both the local binary and a build of `charly` `origin/main`. The docs now
  name that dependency, give the backend that does work (`~/.config/charly/config.yml`
  → `keyring_keys: charly/secret/<NAME>`), and the gap is filed as
  **opencharly/charly#995**.
- **The quickstart could not have run.** It omitted both mandatory admin values; the
  config path stops on `missing required credential-backed secret(s)` instead of
  generating a password. Both `charly config` invocations now carry them.

### Three things the diff does NOT do, and why

- **No inline `skill:` body restored.** PR #9 relocated it to
  `.agents/skills/openwebui/SKILL.md`, and `kind:skill` accepts that shape once the
  provider is current (`plugin-harness-kind` v0.2026288.x makes `content` optional).
  `charly.yml` is untouched by design.
- **Dead declarations, the OpenAI base-URL default, and the Jupyter token `env_accept`
  are not touched** — each surfaced in the audit and each changes the deploy contract,
  needing its own proof. Filed as #11.
- **One known survivor, named rather than implied fixed:** the entrypoint's error hint
  still suggests `charly secrets set …` (`openwebui-entrypoint:138`). Two things make
  that tolerable for now and neither is "it would cost a rebuild": the same hint prints
  the working `charly config -e WEBUI_ADMIN_PASSWORD=…` two lines further down, so no
  user is stranded; and the durable fix is the missing verb itself, not the sentence —
  editing the string would leave the hint pointing at a verb that still does not exist.
  Tracked in #995 with the docs above.

### Provenance and the diffstat, reconciled

**Provenance.** A box's `candy:` list cannot name a local worktree (only
`@github`/`@oci` refs and bare names), and `discover:`-ing a candy repo registers an
empty identity that panics `deploykit.CandyCopySource` (`CandyMapKey == ""`) — a
capability gap named, not worked around. The build therefore used a byte-identical copy
of the frozen tree, verified at build time and again before the runtime commit:

```
$ sha256sum …   # source worktree vs the built copy
openwebui-entrypoint MATCH   pixi.toml MATCH   pixi.lock MATCH   charly.yml MATCH
```

**Diffstat — the two figures are the same diff under two algorithms.** The earlier
rounds disagreed on the counts because we were measuring with different diff
algorithms, not because either was wrong. This checkout sets
`diff.algorithm = histogram` (`~/.config/git/config`); a tool that runs git without
that config gets git's built-in default (**Myers**). The two align the `pixi.lock`
rewrite differently, which is where the whole gap sits — `pixi.lock` reads as 5337
changed lines under histogram and 5167 under Myers, plus one doc line:

```
$ git diff --numstat origin/main...HEAD          # honors this checkout's diff.algorithm=histogram
154     22      .agents/skills/openwebui/SKILL.md      →  176 changes
34      14      README.md                              →   48 changes
12       3      openwebui-entrypoint                   →   15 changes
2505    2832    pixi.lock                              → 5337 changes
1        1      pixi.toml                              →    2 changes
→ 2706 insertions / 2872 deletions   (matches `git diff --stat`'s summary line here)

$ git diff --numstat --diff-algorithm=default origin/main...HEAD   # git's built-in default: Myers
153     21      .agents/skills/openwebui/SKILL.md      →  174 changes
34      14      README.md                              →   48 changes
12       3      openwebui-entrypoint                   →   15 changes
2420    2747    pixi.lock                              → 5167 changes
1        1      pixi.toml                              →    2 changes
→ 2620 insertions / 2786 deletions
```

Both are reproducible from this head with the flag shown; the three small files agree
under either algorithm, which is the check that says the difference is alignment, not
content. A reviewer reproducing the numbers should pass the algorithm explicitly —
without a flag, the number you get is your git config's, not the branch's.
