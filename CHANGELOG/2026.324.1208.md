# 2026.324.1208 — feat(openwebui): advance the pin to Open WebUI 0.13.4

## Summary

Advances the `openwebui` candy's pin from Open Web UI **0.13.3 to 0.13.4** and re-verifies the
upstream contract the entrypoint projects.

- `pixi.toml` — `open-webui = "==0.13.4"`; `pixi.lock` re-solved (`av 19.0.1 -> 14.0.1` follows
  upstream's constraint).
- `charly.yml` — removes `ENABLE_DIRECT_CONNECTIONS`: 0.13.4 removes Direct Connections
  (Tether replaces it), so the candy no longer advertises a setting upstream ignores.
- The 0.13.4 re-verification: TTS/STT/OpenAI-compatible names unchanged;
  `TOOL_SERVER_CONNECTIONS` is still Streamable HTTP only; `WEBUI_SECRET_KEY` is still a hard
  requirement; image generation now reads `images.connections` from the config table, with the
  legacy `IMAGE_GENERATION_ENGINE`/`COMFYUI_*` env seeded into the `image_generation.*` defaults
  and converted by a one-shot startup migration. With `ENABLE_PERSISTENT_CONFIG=false` the
  env-built defaults are re-derived on every start.
- The skill's contract table, the layer skill's env table and the README version claims are
  updated.

This is a compatibility bump only: no new provider feature, no entrypoint change. The full local
configuration (TTS/STT/Strata/ComfyUI/Ollama) is deploy-time env.

**Dependency:** the bed exposed a real `plugin-openwebui` incompatibility (`save` still required
the removed `ENABLE_DIRECT_CONNECTIONS`); the fix is opencharly/plugin-openwebui#3. The consumer
`distro-cachyos` change pins that plugin's CalVer tag alongside this candy's.
