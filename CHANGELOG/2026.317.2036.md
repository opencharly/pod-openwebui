**What the resolver changed** (`pixi lock`, rc=0): `open-webui 0.12.3 → 0.13.3`, plus what
0.13.3 itself pins — `mcp 1.27.2 → 2.3.0` (SSE transport dropped, `httpx-sse` removed),
`httpx2 2.15.1 → 2.16.0`, `uvicorn 0.51.0 → 0.54.0`, `pillow 12.3.0 → 13.0.0`,
`cryptography 48.0.0 → 48.0.1`, `pypdf 6.7.5 → 6.21.2`, `aiohttp 3.14.3 → 3.14.5`.

**Four contract verdicts corrected by the re-verification** (all evidenced in the skill):

1. `ENABLE_PERSISTENT_CONFIG` — the old prose was false: `import_legacy_config_json` runs
   unconditionally and, with persistence OFF, writes into the in-memory defaults, which
   `seed_defaults` then skips — so a migrated `config.json` shadows env for exactly one start,
   and the rename bounds it, not the flag.
2. `TOOL_SERVER_CONNECTIONS` — shape unchanged, but the transport is now **Streamable HTTP
   only**.
3. `CODE_EXECUTION_*` — names unchanged; the consumer now reads the per-key config table, and
   0.13.3 adds a `CODE_INTERPRETER_*` twin that defaults from them (the entrypoint already
   sets both).
4. `WEBUI_SECRET_KEY` — verdict holds, evidence re-pointed (`env.py:774-777,792-800`).

**Three pre-existing false claims in `openwebui-layer` corrected** (found while re-verifying;
they are documentation truth in this repo, so they land here rather than being filed away):
the provider-detection list claimed the SINGULAR `OPENAI_API_KEY`/`OPENAI_API_BASE_URL` and
`https://api.ollama.com/v1` — the entrypoint exports the PLURAL index-aligned lists and
`https://ollama.com/v1`, and it has a key-alone direct-OpenAI path; and the
`TOOL_SERVER_CONNECTIONS` example carried an empty `info.id`, which collapses every MCP server
onto one identity.

**Nothing in the entrypoint changed.** All nine env-var projections it relies on survive
0.13.3 unchanged (`DATA_DIR`, `WEBUI_SECRET_KEY`, `WEBUI_AUTH`, `WEBUI_ADMIN_*`,
`OPENAI_API_BASE_URLS`/`OPENAI_API_KEYS`, `TOOL_SERVER_CONNECTIONS`, `CODE_EXECUTION_*`,
`ENABLE_OLLAMA_API`/`OLLAMA_BASE_URL`), and the Python constraint is identical
(`>=3.11,<3.13.0a1`).

**What this PR does NOT prove, and where that proof lives.** The composed image is proven by

`box validate` over the real tree + the resolver. That is why the commit tier is *analysed on a
live system*, not *fully tested and validated*.

**Operational note for the deployment upgrade:** 0.13.3 adds **six Alembic revisions**
(0.12.3 head `0bd252b206fb` → 0.13.3 head `9f6c2a8d1b43`, all additive). Migrations run at
import and re-raise, and an old image against the migrated DB dies with
`CommandError: Can't locate revision identified by …` — so the live upgrade snapshots
`/opt/data` FIRST and rolls back by restoring it, never by re-tagging the image alone. That
procedure is the deployment-side step, not a property of this diff.

**Environment note (not a repo defect):** `pixi` on PATH is a mise shim that aborts
(`mise ERROR No version is set for shim: pixi`) because neither the umbrella nor this repo
declares a pixi version; the installed 0.82.0 binary was invoked by absolute path, which is
the same binary the shim would have exec'd. Worth a separate host-side fix; it is not something
this repo can declare its way out of.
