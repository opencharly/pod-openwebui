# 2026.293.2307 — fix(openwebui): a declared key must configure a provider, and two contract gaps closed

## Summary

Three of the four follow-ups from #11. The fourth — regenerating the marketplace corpus — is a
different repo and stays open there.

**1. `OPENAI_API_KEY` alone now configures the provider.** This is the real defect. The
entrypoint required **both** the key and `OPENAI_API_BASE_URL`:

```bash
if [ -n "${OPENAI_API_KEY:-}" ] && [ -n "${OPENAI_API_BASE_URL:-}" ]; then
```

…so the `secret_accept` this candy advertises did nothing on its own: a user set the documented
secret, no provider appeared, and nothing told them why. The **key** is what declares the
provider; the URL only says which endpoint. It now defaults to `https://api.openai.com/v1` when
unset, an explicit URL still wins, and with neither set no provider is invented.

**2. `CODE_EXECUTION_JUPYTER_AUTH_TOKEN` had no way in.** The entrypoint already forwards it to
both `CODE_EXECUTION_*` and `CODE_INTERPRETER_*` when it detects a jupyter MCP server, but the
candy declared no `env_accept` — so an authenticated Jupyter could only be wired with
`charly config -e`. Declared.

**3. The immich declarations are removed, not parked.** An earlier revision of this PR kept
them with a "contract participation" note. That was wrong twice over: my own measurement said
the compose generates *either way*, so the justification contradicted the evidence, and a
touched module with dead declarations is exactly the split R1 forbids. They are now **deleted**
from this candy — the `immich` candy self-accepts its own URL for its own container, and
`hermes` is the real consumer of the provide. The stale comments in `pod-immich` that named
`openwebui` as a consumer are corrected in **opencharly/pod-immich#10**.

The new branch is asserted by two **build-scope** plan checks in this candy. A stub
`open-webui` on `PATH` captures what the entrypoint *would* exec, which is the projection under
test (R8: the artifact, not the script text):

```yaml

         URL to the upstream endpoint — the declared secret must work without a second variable
  id: entrypoint-openai-key-alone
  stdout:
    - contains: "OpenAI-compatible at https://api.openai.com/v1"
    - contains: "PROJECTED=https://api.openai.com/v1"
- check: with no provider variables set the entrypoint invents no provider
  id: entrypoint-openai-absent

```

**Build scope is deliberate, and the mechanism is worth recording:** `check live` resolves the
**published** candy from the image's candy labels, so a runtime-scoped step here is skipped in
*both* phases (measured: `check-image` SKIPped it as runtime while `check-live` ran an older
candy's five-step plan). At build scope, `check image` runs the candy this tree actually built.
